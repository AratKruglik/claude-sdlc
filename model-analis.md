# Який реальний таск якій моделі: Fable 5 / Opus 5 / Sonnet 5 / Haiku 4.5

**Станом на 24 липня 2026.** Версія 2 — з урахуванням релізу Opus 5 і виправленням трьох фактичних помилок першої редакції (див. розділ «Що виправлено»).

---

## 1. Коротка відповідь

- **Sonnet 5** — робочий кінь на 80–90% щоденної розробки.
- **Opus 5** (вийшов сьогодні) — новий дефолт для складної агентної роботи, архітектури, plan-фази та фронтенду з високими вимогами до візуалу. Ціна не змінилась відносно Opus 4.8 ($5/$25), а якість — стрибок.
- **Haiku 4.5** — субагенти-екзек'ютори, extraction, механічні задачі великого обсягу.
- **Fable 5** — козирна карта для рідкісних довгих автономних job-ів; token-hungry і в підписках нестабільна.

Головна теза релізу Opus 5: **тюньте `effort`, а не перемикайте моделі**. Це тепер основний важіль.

\* The Decoder дає 21.1% — розходження між вторинними виданнями.

**Чого Anthropic НЕ опублікувала для Opus 5:** SWE-bench Verified і Terminal-Bench. Усі цифри, що ходять мережею (Vals.ai ~97% SWE-bench Verified, Artificial Analysis ~89% Terminal-Bench v2.1 at max effort, BenchLM 79.2% SWE-bench Pro) — **сторонні, harness-залежні**, не від лабораторії.

**Для довідки, старіші офіційні цифри:** SWE-bench Verified — Fable 5 = 95.0%, Opus 4.8 = 88.6%, Sonnet 5 ≈ 85.2%, Haiku 4.5 = 73.3%.

**Практичний висновок:** розрив SWE-bench Verified vs Pro (~20–25 п.) — властивість бенчмарку, не моделі. Різні harness-и дають різницю 10–20 пунктів на тих самих вагах. Фінальний арбітр — ваші eval-и на вашому репозиторії, а не лідерборд.

## 4. Task-to-model мапінг

### 4.1 Щоденна рутина

| Задача | Модель | Очікувана якість |
|---|---|---|
| Код-рев'ю звичайного PR | **Sonnet 5** | Висока; ловить root-cause на brownfield |
| Код-рев'ю перед релізом / критичне | **Opus 5** | Найвища; ловить subtle баги, які Sonnet пропускає |
| Рефакторинг 1–кількох файлів | **Sonnet 5** | Висока |
| Крос-файловий рефакторинг | **Opus 5** → Fable 5 якщо дуже великий | Дуже висока |
| Типові багфікси | **Sonnet 5** | Висока |
| Складний дебаг | **Opus 5** | Знаходить root-cause, а не симптом |
| Написання тестів | **Sonnet 5** (стаби — Haiku) | Висока |
| Документація / README | **Sonnet 5** | Висока |
| Драфти листів, повідомлень | **Sonnet 5 / Haiku** | Достатня |
| Самаризація, research | **Sonnet 5**; Haiku на об'єм | Достатня–висока |
| Data extraction | **Haiku 4.5** | Достатня для структурованого |
| Commit-меседжі | **Haiku 4.5** | Достатня |
| Пояснення коду | **Sonnet 5**; Haiku на просте | Висока |

### 4.2 Дизайн і фронтенд

**Opus 5 — найпомітніший стрибок саме тут.** Клієнти раннього доступу описують дві речі:

- Fabian Hedin (Co-Founder, Lovable): *«It isn't just better on our hardest agentic coding tasks, up 22% over Opus 4.7, it's steadier, with far less variance run to run. For the millions of builders on Lovable, that consistency is the whole game.»*
- Madhav Jha (Co-Founder & CTO): *«Claude Opus 5 is the biggest leap in the Opus family since 4.5. On the same full-stack app builds, the front end shows it first: the best animations, games, and 3D work we have seen from an Opus model.»*
- AJ Orbach (Co-Founder & CEO): модель відкриває власні сторінки в браузері на desktop- і phone-ширині, ловить товар, схований під мобільним фолдом, і checkout-кнопку за межами екрана — і виправляє **до** того, як віддати роботу.

**Розкладка:**

| Задача | Модель |
|---|---|
| Production UI/UX, дизайн-система | **Opus 5** + плагін `frontend-design` |
| Швидка «pixel-perfect» верстка | **Sonnet 5** |
| Фронтенд зі скриншоту, найскладніші one-shot | **Fable 5** (лідер WebDev Arena, 1653 Elo) |
| Механічна генерація компонентів за жорсткою специфікацією | **Haiku 4.5** |

**Критична засторога про естетику.** «Сира» генерація тяжіє до distributional convergence: Inter, фіолетові градієнти, безпечні layout-и — «AI slop». Це не лікується вибором моделі, це лікується **плагіном `frontend-design`** (Anthropic-verified; React/Vue/Svelte/HTML) плюс вашим стилем у `CLAUDE.md` (палітра, spacing, явне «no generic AI aesthetics»). Claude Code без цього оптимізує під «щоб працювало», а не «щоб виглядало».

**Haiku на UI:** компоненти «виглядають правильно», але під поверхнею ховаються логічні помилки, вразливості й неефективність. Погано тримає складні бізнес-вимоги й багатофайлове міркування. Для дизайну — тільки під чітку специфікацію й з рев'ю.

### 4.3 Презентації (pptx)

Claude робить **нативні, повністю редаговані .pptx** через Code Execution / File Creation або add-in у PowerPoint.

- **Opus 5** — для мультикрокових деків: розуміння даних + бренд-гайдлайни + дизайн-рішення + генерація файлу + самоперевірка. Партнер раннього доступу зазначив, що найбільший приріст — саме на довгогоризонтних задачах типу «побудувати повний дек, потім переробити»: краще візуальне розуміння, чистіше форматування, менше поламаних слайдів.
- **Sonnet 5** — швидкі й прості деки; для щоденного вистачає, але не дасть топ-якості на складних даних.
- **Haiku** — не варто.

**Реальні обмеження:** add-in дає ~85% бренд-відповідності (2–4 год ручного доопрацювання на дек); один дек з'їдає значну частину квоти Pro (є звіти про ~30% сесійного ліміту); візуальна якість add-in найслабша серед Claude-поверхонь. Для вебінарних матеріалів: генеруйте структуру й контент у Claude, полірування — вручну.

## 5. Економіка та маршрутизація

**Ключова метрика — вартість завершеної задачі, а не ціна за токен.** Opus 5 на CursorBench дає майже піковий результат Fable 5 за половину вартості на задачу — тобто дорожча за токен модель може виходити дешевшою за результат.

**Патерни, що працюють:**

1. **`opusplan` у Claude Code** — Opus для плану в plan mode, автоперемикання на Sonnet для генерації. Спільнота повідомляє про 60–80% економії з мінімальною втратою якості.
2. **Маршрутизація субагентів** — planner на Opus, worker-и на Haiku/Sonnet, reviewer на Sonnet. Haiku ~15× дешевший за Opus; на read-only задачах (file search, grep, прогін тестів, lookup) результат еквівалентний.
3. **Три-тірна схема** (Opus — архітектура, Sonnet — імплементація/тести, Haiku — швидкі правки) — ~51% економії проти uniform-Opus.
4. **Гігієна контексту** — `/compact` і `/clear` між задачами ріжуть повторне пересилання на 30–50%. Стабільний контекст тримайте в `CLAUDE.md` (кешується зі знижкою; тепер від 512 токенів).

**Пастка:** якщо встановлена env-змінна `CLAUDE_CODE_SUBAGENT_MODEL`, вона **перекриває всю маршрутизацію** — субагенти тихо успадковують дорогу модель. Перевірте перед оптимізацією.

**Fable 5 token-hungry:** користувачі Max 20x повідомляють про ~2% денної квоти за хвилину інтенсивного використання; одна сесія з'їдає 10–20% денного ліміту.

**Плани:** на Pro Opus і Sonnet ділять один пул — довга Opus-сесія з'їдає Sonnet-headroom. На Max — окремі бакети. Для вашого профілю (щоденна розробка + запис контенту + консалтинг) — **Max 20x**. Якщо основне навантаження це API-пайплайни, рахуйте через API-білінг і моніторте 429.

## 6. Breaking changes Opus 5 — обов'язково для агентних пайплайнів

Це найважливіша частина для вашої SDLC-архітектури:

1. **Thinking увімкнено за замовчуванням** (на 4.8 запити йшли без нього, поки не задано adaptive). Перегляньте `max_tokens` — він тепер включає токени мислення.
2. **Вимкнути thinking можна лише при effort ≤ `high`.** При `xhigh`/`max` + `{"type":"disabled"}` → **HTTP 400**.
3. **Mid-conversation tool changes (beta)** — хедер `mid-conversation-tool-changes-2026-07-01`: додавати/прибирати інструменти між ходами **без інвалідації prompt cache**. Для мультиагентних систем зі змінним toolset це прямий виграш.
4. **Server-side fallbacks (beta)** — хедер `server-side-fallback-2026-07-01`, режим `"default"` застосовує рекомендовані Anthropic моделі-фолбеки за категорією відмови.
5. **Приберіть старі інструкції на кшталт «include a final verification step» або «use a subagent to verify»** — Opus 5 верифікує сам і починає **надмірно** перевіряти. Це реальний ризик роздування токенів у вашому пайплайні.
6. **Поведінкові зміни без коду:** довші відповіді за замовчуванням, частіше наративить прогрес у агентних сесіях, охочіше делегує сабагентам.
7. **Effort — головний важіль.** Для кодингу й агентних задач стартуйте з `xhigh`. Для рутини low/medium дають хорошу якість за частку токенів і латентності.

**Кібербезпека:** класифікатори дозволяють пошук вразливостей у сирцевому коді, але блокують binary-based vuln scanning, pentesting і генерацію експлойтів. Anthropic очікує, що класифікатори спрацьовуватимуть приблизно на 85% рідше, ніж для Fable 5. Є Cyber Verification Program з менш обмеженою версією.

**Safety:** ASL-3 (як Opus 4.8), CB-1 але не CB-2, поріг автоматизованого AI R&D не перетинає. За внутрішнім поведінковим аудитом — найбільш вирівняна модель Anthropic (2.3 бала misaligned behavior). Позаду Mythos 5 у наступальній кібербезпеці та біології.

**Fallback Fable 5:** для кібер- і загальних відмов класифікатора — усе ще на Opus 4.8. **Але біологічні запити тепер маршрутизуються на Opus 5**, а не на 4.8.

## 7. Стартова конфігурація для вашого профілю

1. **Дефолт — Sonnet 5** на всю щоденну розробку.
2. **Ескалація на Opus 5** для: складного дебагу, крос-файлових рефакторів, архітектурних рішень, plan-фази (`opusplan`), фронтенду з високими вимогами до візуалу, мультикрокової генерації презентацій.
3. **Haiku 4.5 на субагентів** — явно виставляйте `model: haiku` у YAML. Extraction, commit-меседжі, стаби тестів, механічна генерація.
4. **Fable 5 — тільки як козир** для рідкісних довгих автономних job-ів, і краще через API (де завжди доступний), а не через нестабільну підписку. Давайте повне, добре сформульоване завдання — це асинхронний агент, не чат-партнер.
5. **Обов'язково поставте `frontend-design`** — без нього навіть топові моделі дають AI slop.
6. **Проревізуйте свій пайплайн** під breaking changes з розділу 6 — особливо пункти про thinking-за-замовчуванням, `max_tokens` і зайві verification-інструкції.

**Пороги для перегляду рішення:**

- Sonnet 5 регулярно не завершує клас задач або потребує кількох ретраїв → підніміть цей клас на Opus 5 (кращий perf-floor, менша варіативність run-to-run).
- Opus 5 впирається у стелю на найважчих 10–20% або дуже довгих прогонах → пробуйте Fable 5, але лише коли вартість провалу перевищує токен-дельту.
- Слідкуйте за появою офіційних SWE-bench Verified / Terminal-Bench для Opus 5 і за WebDev Arena Elo — станом на сьогодні їх немає.

## 8. Що виправлено відносно першої редакції

Три фактичні помилки, знайдені при перевірці проти першоджерел:

1. **Цитата про самоперевірку фронтенду приписувалась Vercel.** Насправді автор — **AJ Orbach (Co-Founder & CEO)**. **Vercel в анонсі Opus 5 взагалі не згадується** (перевірено повний список із 22 цитат клієнтів).
2. **Цитата Fabian Hedin була склеєна з окремою цитатою Madhav Jha.** Розділено вище.
3. **Сходинка `effort` подавалась як чотири рівні.** Насправді **п'ять**: low / medium / high / **xhigh** / max.

Плюс перекваліфіковано: **SWE-bench Pro 79.2% для Opus 5** — це не офіційне число Anthropic, а показник стороннього агрегатора **BenchLM** невисокої авторитетності. Сам BenchLM зазначає, що липневий аудит OpenAI визнав ~30% публічних задач SWE-bench Pro «зламаними» і відкликав рекомендацію.

Також відокремлено: **зміни rate limits планів** (подвоєння 5-годинних лімітів Claude Code від 06.05.2026; +50% тижневих до 19.08.2026; перехід Fable 5 на usage credits від 20.07.2026) — це **паралельні події**, а не частина релізу Opus 5.

## 9. Застереження

- **Opus 5 вийшов сьогодні.** Незалежні бенчмарки ще накопичуються. Більшість цифр — Anthropic-reported із власних бенчмарків (Frontier-Bench, CursorBench, GDPval-AA), а не стандартні SWE-bench Verified / Terminal-Bench. Партнерські цитати — це маркетинг раннього доступу.
- **Vendor-бенчмарки** (CursorBench, Aider, Frontier-Bench) контролюються зацікавленими компаніями. Ставтесь як до self-reported.
- **Ціни й ліміти змінюються часто** — Anthropic коригувала ліміти Claude Code чотири рази між березнем і червнем 2026. Інтро-ціна Sonnet 5 діє до 31.08.2026.
- **Оцінки якості дизайну й презентацій** частково спираються на маркетингові матеріали й окремі практичні звіти, а не на строгі публічні eval-и. Валідуйте на своїх задачах.
- Приналежність AJ Orbach до конкретної компанії встановлена за зовнішніми профілями (лого в анонсі подано зображенням). На головний висновок не впливає: це не Vercel.
